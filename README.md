# YEET ARENA

**Chaos is a combat sport.**

A complete 2D arcade fighter: Godot 4.7 client, Python FastAPI + SQLite leaderboard,
procedurally drawn fighters, synthesised audio, a shrinking cage and exactly one
button that ends arguments — **YEET**.

```
   Y E E T   A R E N A
   six fighters · three arenas · one shrinking cage
```

---

## What this is

A portfolio-scale, end-to-end game project. Every part is original and buildable
from the repository:

| Layer            | Tech                                   | Where |
| ---------------- | -------------------------------------- | ----- |
| Game client      | Godot 4.7.x (GDScript, no external assets) | `game/` |
| Fighter art      | procedurally drawn polygons at runtime  | `game/scripts/effects/fighter_art.gd` |
| Audio            | synthesised WAVs (pure Python stdlib)   | `tools/generate_audio.py` → `game/assets/audio/` |
| Leaderboard API  | FastAPI + SQLite (stdlib `sqlite3`)     | `backend/app/` |
| Backend tests    | pytest + FastAPI TestClient (22 tests)  | `backend/tests/` |
| Game tests       | headless Godot scenes                   | `tests/godot/` |

No sprite sheets, no stock sound packs, no placeholder art: the fighters are
articulated skeletons drawn in `_draw()`, the arenas are procedural skylines, and
the 25 audio files are generated by a script you can read.

## Quick start

### 1. Get Godot 4.7.x

The engine binary is **not** included in this repository (it is ~100 MB).
Download Godot 4.7.x (standard, not .NET) from
<https://godotengine.org/download/windows/> and either

* put it on your `PATH`, or
* copy the executable to `tools\godot\godot.exe`, or
* set an environment variable once:

```bat
setx GODOT_BIN "C:\Godot\Godot_v4.7.2-stable_win64.exe"
```

### 2. Play

```bat
start_game.bat
```

It launches the game and, if it is not already running, starts the leaderboard
backend in a second window. The game is fully playable **offline** — scores are
kept in-memory and the results screen simply reports that the leaderboard is
unavailable.

To run the leaderboard separately:

```bat
start_backend.bat            # http://127.0.0.1:8000  (interactive docs at /docs)
```

### 3. Run every test

```bat
run_tests.bat
```

Runs the pytest suite, the headless Godot menu smoke test, a complete scripted
arcade match, and a live client↔backend integration test.

## Controls

| Action              | Keys |
| ------------------- | ---- |
| Move                | `A` / `D` or `←` / `→` |
| Jump                | `W` / `Space` / `↑` |
| Light attack        | `J` |
| Heavy attack        | `K` |
| **YEET** (special)   | `L` |
| Dash (i-frames)     | `Shift` |
| Guard (hold)        | `S` / `↓` |
| Pause               | `Esc` |
| Menus               | mouse, arrows, `Enter`, `Esc` |

Every action uses a **0.16 s input buffer**, so inputs are not lost during
recovery frames.

## Fight system

* **Combo scaling** — damage decays across a combo (`max(0.45, 1 − 0.07·(n−1))`).
* **Guard** — hold down; blocks most damage but you are still pushed.
* **Parry** — GLITCH only: tap guard on the last frames of an incoming hit to
  hard-counter it.
* **Super armour** — BRICK only: light and heavy hits will not interrupt him.
* **YEET** — a slow, huge, edge-latched special. Release the key to re-arm.
* **Hitstop + shake** — every solid hit freezes and punches the camera.

## The shrinking cage

Every match contracts the safe zone three times (15 s, 35 s, 47 s) with a
telegraphed warning. Outside the border you take escalating chip damage, so the
last 15 seconds of a match are a brawl in a phone booth.

* `neon_pit` — no hazard, pure fighting.
* `reactor_core` — periodic vent blasts.
* `void_circuit` — drifting energy orbs.

Matches last 60 seconds, end on K.O. or the clock, and are scored as
`damage ×10 + max_combo ×60 + KOs ×500 + time_left ×15 + HP_left ×5 + 1500 for a win`
(see `docs/DESIGN.md`).

## Backend API

Base URL `http://127.0.0.1:8000` (configurable in the game's settings screen or
via `YEET_API_URL`).

| Method | Path | Purpose |
| ------ | ---- | ------- |
| `GET`  | `/health` | liveness + total match count |
| `GET`  | `/api/scores?limit=&offset=&fighter=` | leaderboard page + total count |
| `GET`  | `/api/stats` | aggregate stats (averages, top fighter, per-fighter rows) |
| `POST` | `/api/scores` | submit a match result, returns `{"rank": N, ...}` |

Design notes:

* validation mirrors the client one-to-one (`player_name` 2–16 visible chars,
  known fighter, score ≤ 5,000,000, duration ≤ 600 s, strict booleans …);
* `client_match_id` is uniquely indexed, so retrying a submission returns
  `409` instead of duplicating a score;
* submissions are rate limited (30 per minute per IP → `429`);
* ranks are scoped per mode, so `demo` runs never outrank `arcade` runs;
* the database file path is configurable with `YEET_DB_PATH`.

```bash
# example submission
curl -X POST http://127.0.0.1:8000/api/scores -H "Content-Type: application/json" -d "{\"player_name\":\"NOVA\",\"fighter\":\"volt\",\"opponent\":\"brick\",\"mode\":\"arcade\",\"score\":4820,\"kos\":2,\"max_combo\":7,\"duration\":58.4,\"victory\":true,\"client_match_id\":\"m-1\",\"client_version\":\"1.0.0\"}"
```

## Testing

```bash
cd backend && python -m pytest            # 22 API tests
```

```bat
run_tests.bat                             # everything, including Godot
```

The Godot tests are ordinary scenes: they boot the real router, play a real
match and talk to the real backend. Run them by hand with:

```bat
"%GODOT_BIN%" --headless --path . --fixed-fps 60 --quit-after 6000 res://tests/godot/match_test.tscn -- --no-audio
"%GODOT_BIN%" --headless --path . --quit-after 6000 res://tests/godot/api_test.tscn -- --no-audio
```

(`-- --no-audio` disables playback in test runs; drop it to hear the game while
testing, and skip `--fixed-fps` for the API test — it needs wall-clock time.)

See `VERIFICATION_REPORT.md` for the exact commands and outputs of the last full
verification run.
